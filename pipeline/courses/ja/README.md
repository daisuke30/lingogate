# LingoGate — JA Course Data (LINGO-044)

Japanese course: **Japanese (spoken-frequency bands)**, prompted in English or
Russian (裏面=Japanese, 表面=en/ru). Same JSONL→pack pipeline as the RU/EN/TH
courses with its own data directory; the other three are untouched.

Built on the method the Thai course (LINGO-039) established, with one large
difference called out throughout: **Japanese inflects**, so the trick that made
Thai safe — computing the sentence from its dictionary forms — does not apply,
and the guarantee has to be obtained another way.

## Files

| File | What it is |
|---|---|
| `words_band1.jsonl` | Ranks 1–1000. `{lemma, rank, band, pos, kana, reading, romaji, en_gloss, ru_gloss, source}`. |
| `words_band2.jsonl` | Ranks 1001–2000. Same schema. Vocabulary only. |
| `words_band3.jsonl` | Ranks 2001–3000. Same schema. Vocabulary only. |
| `sentences_band1_core.jsonl` | Band1 core sentences, one per band1 word. `{id: "JA####", ja, kana, en, ru, lemmas[], target_lemma, difficulty, kind, note?, note_en?, note_ru?}`. |

`reading`, `romaji` and `source` are provenance/detail; the app reads `kana`
(which combines the first two). No `ja_gloss`: the headword already *is*
Japanese.

## Word list source & license

**wordfreq** (`ja` list) — Robyn Speer's multi-source frequency library,
**Apache-2.0**. Its Japanese list merges several corpora (subtitles, web text,
Wikipedia and others) and is tokenised with MeCab rather than on whitespace,
which is the property that matters: Japanese, like Thai, has no spaces, so a
whitespace-tokenised list would be measuring line breaks.

Chosen over a written-corpus list (BCCWJ) because this course is aimed at
conversation — the brief asked for a spoken-leaning source — and because
BCCWJ's own download endpoints did not resolve in this environment. wordfreq's
spoken lean is visible in its own top entries (です, ます, ね, よ, てる).

## Readings — the load-bearing field

**fugashi + unidic-lite (UniDic)** supplies every reading. This is the whole
quality story of the course, for the same reason tone was in Thai: a learner
cannot get a Japanese reading out of the script, and the reading is
**context-dependent** — 人 is ひと alone but にん in 三人, 今日 is きょう but
こんにち in 今日は. Only a morphological analyser can be trusted with it, so
**no reading anywhere in this course was generated by a model.**

Every word carries both a **furigana reading** and a **Hepburn romanisation**;
`kana` holds `"よみ / romaji"`, or just the romaji when the headword is already
kana (repeating こんにちは under こんにちは teaches nothing).

### Three UniDic fields, three different jobs

Getting these confused produces wrong readings, and each mistake below was
actually made and then caught:

| field | what it is | used for |
|---|---|---|
| `lForm` | the **lemma's** dictionary reading | the word list's reading |
| `kana` | this token's reading **in context** | the sentence's reading |
| `pron` | actual **pronunciation** | romaji, particles only |

- Using `kana` for the word list gave 箱 the reading **バコ** — the rendaku form
  it takes inside compounds (ゴミ箱). `lForm` gives ハコ, which is the word.
- Using `pron` for romaji gave **sensē** and **ōkī**: `pron` collapses every
  long vowel to ー (センセイ→センセー, オオキイ→オーキー), destroying the ei/ou/oo/ii
  distinctions Hepburn keeps. `kana` yields sensei / ookii / arigatou.
- But `kana` is wrong for the *particles*, whose spelling and sound differ by
  rule: は is read **wa**, へ is **e**. Those tokens — and only those — take
  their romaji from `pron`. Same for the greetings that end in the particle は
  (こんにちは → `konnichiwa`, not "konnichiha").

Romanisation is **modified Hepburn**, faithful to the kana spelling (`toukyou`,
`sensei`, `ookii` rather than macrons), with `n'` before a vowel or y
(`kin'en`). Written as an explicit kana table in `build_ja_vocab.py` so the
convention is visible and testable; a reading it cannot romanise is rejected
rather than half-transcribed.

## What is in band1, and what was filtered out

A frequency list of Japanese *surface forms* is not a vocabulary list, and two
structural corrections were needed.

**1. Frequency is aggregated onto the dictionary form.** A Japanese verb occurs
almost entirely as inflected surfaces (食べます / 食べた / 食べて), each counted
separately, so the dictionary form 食べる ranks low. Ranking raw surfaces gave a
band1 of **731 nouns and 48 verbs** — useless for building sentences. Adding
each surface's frequency mass to its own dictionary form (UniDic `orthBase`)
gives **650 nouns / 140 verbs / 70 adjectives / 47 adverbs**.

**2. Function words are curated, not ranked.** Analysed out of context, て / た /
し / って / たら / れ / さ all look like top-30 "words", but none is a vocabulary
item — they are inflectional fragments. The closed class (particles, copula,
です・ます, conjunctions) is therefore a hand-picked list of ~38 entries merged
in at the front, and open-class words come from frequency. Hand-picking a
closed class is both more accurate and shorter than any filter separating it.

**Greetings are curated too** (the analogue of the Thai course's travel core):
すみません analyses as 済む+ます+ぬ, ありがとう normalises to 有り難う, こんにちは to
今日は, so a frequency list cannot represent them as words at all — yet they are
the first thing a beginner needs. 23 such entries are promoted to the front of
band1.

**Rejected by the "the reading must be certain" gate**: inflected forms
(`orthBase` ≠ surface), person names (UniDic tags a surprising number of
ordinary-looking tokens as one — 周 came back as the given name シュウ, 達 as
トオル; place names like 日本 and 東京 are kept), bound morphemes (的, 者, 製,
買い), single kanji whose isolated reading is genuinely indeterminate (出, 分,
上, 下, 間), and single hiragana reaching the open-class path (always a
fragment). A handful of individually-flagged entries (多 read さわ — a name
reading; なれ = archaic 汝; かい = 甲斐) are listed in `EXCLUDE` with reasons.

Nine reading overrides are recorded in `OVERRIDES`, each with its reason —
私→わたし (UniDic defaults to the formal ワタクシ), 言う→いう, 日本→にほん,
枚→まい, いい→いい, 室→しつ.

## Sentences

One sentence per band1 word, `id` number == that word's rank, **3–8 tokens**,
polite **です・ます** style, everyday beginner topics (self-introduction, family,
food, shopping, directions, time, weather, work, feeling unwell).

3–8 rather than the 3–7 used elsewhere because Japanese counts differently:
particles and です/ます are separate tokens, so 私は学生です is already 4 and
駅はどこですか is 5 with only two content words. 8 is also the hard ceiling in
`build-content.mjs` (`MAX_SENTENCE_TOKENS`) above which a sentence is dropped.

### The text is written; everything else is derived

The Thai pack could *compute* its sentence text by concatenating dictionary
forms, because Thai is isolating. Japanese cannot: 食べる appears as 食べます.
So the generation batches write a real, inflected sentence, and the assembler
derives the rest by running UniDic over it:

```
tokens  -> surface + reading + dictionary form
kana    -> the furigana of the whole sentence + its Hepburn, per token
lemmas  -> the dictionary forms, which is what links to the deck
```

The machine verification that replaces Thai's structural guarantee:

- the tokenisation must **round-trip** (the concatenated surfaces must equal the
  original sentence), or the reading built from it is not this sentence's;
- **every lemma must be a deck word** — the Thai pack got this for free, here it
  is enforced, and a sentence using an off-vocabulary word is rejected outright;
- the target lemma must actually appear in its own sentence;
- 3–8 tokens, no duplicate sentences, `en` ASCII-with-no-Japanese, `ru` Cyrillic;
- notes are all-three-languages or absent (a partly-translated note either leaks
  or silently vanishes — LINGO-037 finding #4).

Word-list reading overrides are applied inside sentences too, so a card's
furigana can never disagree with that word's own vocabulary entry.

## Course visibility (LINGO-044's second half)

`selectableCourses(uiLang, activeCourseId?)` in `web/src/content/courses.ts`
hides any course whose target language is the UI language — a Japanese-speaking
user is not offered "learn Japanese". It is the course-level counterpart of the
rule `availableFrontLangs` already enforced at the prompt level, and the two are
asserted to agree. The course currently being studied is exempt, so switching
the UI to Japanese mid-course does not make the course vanish.
